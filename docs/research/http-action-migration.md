## Hypeddit

It posts form-encoded data to `/verifyEmailAddress` with exactly `validateEmailAddress`, `fan_gate_id`, `email_name`, `adcode`, and `hypesource`. `performHypedditAction('prepare-email')` starts a bounded same-origin HTTP job and remains synchronous for the existing provider contract. `hypedditActionProgress` reports the HTTP result. Pending work is deduplicated. Session rejection, rate limits, non-JSON/redirected responses, oversized responses, failures, and a twelve-second timeout cannot become completion. Declared CAPTCHA and native attempt-limit state stop the request. No challenge token is manufactured or read.

A successful request retains the generated dictionary-word iCloud placeholder and the verification name in the current document/gate's memory. `captureWebsiteRequest` uses that accepted email for the final request. The native email and name inputs are never changed. `email_name` belongs to the proven verification schema; the retained final-download schema sends `email`, not an invented name field.

The retained page's gate-scoped `#login_to_sp` embeds one literal `PopupCenterDual` URL targeting `https://accounts.spotify.com/authorize`, with Hypeddit's own client and `https://hypeddit.com/spotify_callback`, an opaque state, and its native scope. `hypedditAuthUrl` parses that literal as inert text and preserves its exact parameters. It rejects duplicate required parameters, credentials, fragments, unsupported origins/routes/callbacks, and handlers without exactly one literal URL. No new OAuth client or query parameter is generated.

Only an explicit Gatebreaker sign-in activation opens that URL. When the owned window returns or closes, a bounded ordinary `POST /gate/download/ul` checks the current website session and accepted email. Only `download_status === true` with a safe destination confirms whole-gate readiness. That final JSON result stays in the exact document/gate/session memory for at most thirty seconds and the provider resolver reuses it. This handles fast-closing callbacks without requiring a blocked Download button to be pressed again. A closed/cancelled window followed by refusal does not complete that sign-in or any other account requirement.

For gates with multiple native requirements, only the trusted browser `storage` event for the known nonsecret `hypeChildWindow` control-id flag can provide provisional callback progress while final access remains refused. It must match a pending owned window, its originating control id, the native callback origin/path, current session and timeout. No storage token, OAuth query field, password or account page is read. A final-file refusal alone cannot identify which account succeeded. Native carousel classes are never acceptance proof.

## Validation and integration

The authored `http-native-migration.test.ts` fixture checks exact email fields/headers, `T` versus failures, response bounds, CAPTCHA/attempt stops, pending deduplication, memory-only final email, inert authorization URL validation, activation, owned callback path, direct PUSH route navigation, and source/origin/driver rejection. It asserts no native click, input/change event, slide drive, or button mutation. All account, state, token, and CSRF values in fixtures are authored and nonfunctional.

The Hypeddit and PUSH provider wrappers expose required auth only after an actual server refusal. Inspection makes no HTTP requests, so public-file access and existing website sessions can be checked first. Hypeddit's session module avoids an actions/request import cycle and scopes transient verification results to the document, gate and ordinary session fields. The surrounding controller pauses for explicit sign-in activation after discovering those requirements. HTTP status or a callback flag does not establish successful final file access until the provider accepts its final response.

Additional migrated fixtures are staged separately under `test-updates/`: the four existing content/native/PUSH test files and the installed Chrome/Firefox native-action and PUSH automation helpers. They replace native click/slide fixtures with exact request bodies, server-first discovery, owned-window source binding and final HTTP proof. Shared browser builds and installed-browser suites were not run by this subtask.
